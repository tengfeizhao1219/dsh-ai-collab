# ai-collab 机制优化升级报告（v1 → v2 草案）

> 研究来源：① 本项目在真实项目（AI 情报官）中的运行记录实证；② 业界多代理协作框架调研（MetaGPT/ChatDev/AutoGen/CrewAI/LangGraph/Anthropic/敏捷+AI）。
> 状态：草案，待与业界调研合并后定稿。

## 一、实证缺陷分析（来自 AI 情报官真实运行记录）

从 COMMLOG 的踩坑记录与看板运转情况，可反推出机制的 10 个真实缺陷（按严重度排序）：

### 缺陷 1：经验不沉淀 → 同一个坑踩 4 次
**实证**：首页底部遮挡问题修了 4 次（加 padding → 加 spacer → 换掉 scroll-view → 发现 100vh 计入手势条才是根因）。且 One News 首页注释里**早就写了**「transform 内 100vh 在部分机型/Webview 失效，用 --page-h 规避」——同一个坑的解法就在旁边，新模块还是踩了。
**机制缺陷**：没有「教训库」。知识停留在某个角色/某段对话里，没有回流到可检索的文件。

### 缺陷 2：改动不做影响面检查 → 漏层修复
**实证**：时间显示成"今天"实为昨天数据，根因是历史清理**漏了 intel_ingest（raw 层）**——只清了 staged+current。数据层和显示层是两层，修了一层漏一层。
**机制缺陷**：交付没有「影响面清单」（数据层/显示层/部署/兼容性），修复容易顾此失彼。

### 缺陷 3：部署/改动后不验证生效 → "部署成功"≠"生效"
**实证**：cloudbase 部署 intelFetch **首次部署未生效**（日志还是旧格式），重新部署才生效。
**机制缺陷**：没有 smoke test / 生效验证步骤。看板把"已部署"当完成，但实际没验证。

### 缺陷 4：下游无质量闸门 → 占位卡污染上游
**实证**：处理层写 staged 前不校验"一句话定义"，空数据入库 → 调度层用「（定义待补充）」兜底，首页出现 4 条占位卡。
**机制缺陷**：阶段间质量检查没有前置（下游兜底掩盖上游缺陷）。修复方式是加「④.5 质量闸门」——但这应该内建于机制而不是事后补。

### 缺陷 5：owner 拍板无结构化记录 → 决策追溯靠翻记录
**实证**：25 源清单 O 裁决、UA 策略、main 为规范分支——都散落在 COMMLOG 条目里。
**机制缺陷**：没有 ADR（架构决策记录）。决策的"理由/备选/影响"没有结构化保存，后续会话只能猜。

### 缺陷 6：单一事实源被多副本稀释 → 手动同步易错
**实证**：intel-officer 分支退役并入 main 时，WorkBuddy / Desktop / One-News-latest **三副本全要手动切**。
**机制缺陷**：文件即通信的前提是"一个仓库一个事实源"，多副本场景下同步依赖人肉纪律。

### 缺陷 7：一致性校验太晚 → 文档漂移累积
**实证**：文档交叉校验（NAVIGATION 锚点表）在 Phase 0 一次性做过，之后主要靠 Q 角色在 Phase 3+ 介入；期间 TASK_BOARD/RELAY/COMMLOG 的交叉一致性无任何自动检查。
**机制缺陷**：校验靠人（角色）不靠工具，且时机太晚。

### 缺陷 8：交接记录无限膨胀 → 会话继承成本上升
**实证**：COMMLOG 一条修复带多个"子页面"记录，21 篇文档还出现过重复孤儿页。
**机制缺陷**：无归档/压缩策略。五件套越滚越大，新会话读文件的 token 成本线性上升。

### 缺陷 9：无自动化质量门禁
**实证**：看板里几乎没有自动化测试任务（只有 node --check、手动验证），关口检查靠 O 主观判断。
**机制缺陷**：Gate Check 的通过标准没有客观化（无 lint/typecheck/test 门槛）。

### 缺陷 10：无失败恢复状态
**实证**：任务只有 📋/🔄/✅/🚫 四态；子 Agent 中途失败/中断后没有"重试/回退"显式状态，容易在并行中被遗忘。
**机制缺陷**：任务生命周期不完整。

## 三、业界调研结论（MetaGPT/ChatDev/AutoGen/CrewAI/LangGraph/Anthropic/敏捷+AI）

来源：arXiv 2308.00352（MetaGPT）、ACL 2024（ChatDev）、LangGraph 持久执行文档、Anthropic 多智能体系统（ZenML 整理）、Claude Code 记忆文档、Vercel ADR skill、AWS 自主编码代理、Coding Agents in the Wild（IEEE）等。

| 来源 | 可借鉴做法 |
|---|---|
| MetaGPT | **SOP 即工件流水线**：每角色只产出一类结构化工件（PRD→设计→任务→代码→测试），下游只消费上游工件，禁止自由对话 |
| MetaGPT | **可执行反馈**：测试被真实执行，失败信息回灌修正——Gate 由跑脚本判定，不用 LLM 自评 |
| ChatDev | 阶段化管线 + 阶段间交接物是文档 + 里程碑处插入人工确认 |
| LangGraph | **显式状态 + 检查点持久化**：每节点后写完整状态，崩溃从最近检查点恢复；边结构天然禁止跳阶段 |
| Anthropic | **子代理只回结构化摘要**（结论+证据+下一步），主控写进 notes 文件（文件即状态） |
| Claude Code | **记忆分级 + @import 渐进披露**：主文件只放高频不变规则，细节拆子文件按需加载 |
| Claude Code | **记忆卫生**：上下文将满自动压缩为摘要，定期清理失效条目 |
| Vercel ADR | ADR 三要素 Context/Decision/Consequences + proposed→accepted→superseded 状态机 |
| AWS | **DoD 写成显式 ADR**，含人工批准与测试要求；"文档已更新、无 TODO、测试通过"固化为可脚本校验清单 |
| IEEE 实证 | AI 生成 PR 常因**破坏既有测试/缺上下文/未更新文档**被拒 → 转成 Q 的 Gate 清单 |
| vibegates/Codacy | **硬门禁而非建议**：8 类门禁做成 blocking CI + commit 守卫，门禁产出证据随工件归档 |
